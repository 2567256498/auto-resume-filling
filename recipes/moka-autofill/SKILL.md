# Moka 校招简历填写配方（moka-autofill）

适用：Moka 校招候选人端**两类页面**——① 在线简历页 `app.mokahr.com/campus-recruitment/<机构>/<id>#/candidateHome/resume`；② 职位申请表 `app.mokahr.com/campus-recruitment/<机构>/<id>#/job/<jobId>/apply?applyFormId=<id>`。两者字段集与按钮结构都不同（见 §1 末条、§5、§6），套用前先判是哪一类。
首次实战：2026-09-17（投递台账序号 32）。现场侦察重建，只记本系统结构与手法；通用纪律见本手册。

> **通道 = QQ 浏览器**（命令映射见手册 §三）。
> **本通道已复现的动作**：判框架、页面内 JS（完整合成事件序列开层／点选、原型 setter 写入）、`browser_input_text --index` 真实键入、`browser_go_to_url` 真重载均已在本系统跑通；**未复现**的是真实点击开层与 iframe 穿透（开层走事件序列，本配方不依赖二者）。

## 1. 框架与 DOM 骨架

- 框架：React（旧版，元素上挂 `__reactInternalInstance$<hash>` / `__reactEventHandlers$<hash>`），组件为 Moka 自研 `sd-*` 系（非 antd、非 element-ui）。
- 字段容器：`.apply-field-Q2iJ7AtQGX`，标题在子 `.title-IWWQ0Xa4L7`；区块（教育背景／实习经历等）内字段按 DOM 顺序排列，同名标题按出现次序（occ）区分。
- 区块添加按钮：文案「添加」；每条记录另有「删除本条」。
- **页面类型决定按钮结构**：① 在线简历页（实例 A）底部有「保存」按钮，保存＝整页提交，不做逐条保存；② 职位申请表（实例 B）**全页无「保存」按钮**，只有一个「预览并提交」，另有左侧区块导航与底部「更新说明：同步更新在线简历」勾选——此类页面填完**无法自查落库**，只能进预览页。

## 2. 四类控件与写入通道

| 控件 | 识别 | 写入方式 | 值落在哪 |
|---|---|---|---|
| 普通文本输入 | `input`，`maxlength=255`（姓名／所在地／最近公司／证件号码／当前薪资／期望薪资／期望城市／公司名称／职位名称／项目名称／职责／语言类型／奖项名称） | 真实键入：取 snapshot 编码索引 → `browser_input_text --index <idx> --text <值>`（索引每次会变，键入前重取 snapshot） | `input.value` |
| 多行文本 | `textarea`（工作职责／项目描述／项目中职责／自我描述），无 maxlength | 同上；文本内含 `\n` 可真实换行，保存回读后换行保留 | `textarea.value` |
| 字典下拉 | 字段内含 `.sd-Dropdown-container-1CigZ`，`input` 只读展示（性别／工作经验／最高学历／学历／掌握程度／听说／读写／年／月） | **只能点选**：点 input 展开 → 在字段容器内找可见 `.sd-Select-menu-36GwS` → 点 `.sd-Select-common-item-3YCIH` 中文本匹配项 | `span.sd-Input-display-value-RwqDy`（`input.value` 恒为空） |
| 远程联想 | 同下拉结构但可键入（学校名称／专业名称） | 键入后**必须点选候选项**；仅键入不入 React state，后续任何 re-render 会静默清空 | `span.sd-Input-display-value-RwqDy` |

开层与点选都要派发完整合成事件序列（缺一不开层）：
`pointerover → mouseover → pointerdown → mousedown → focus → mouseup → pointerup → click`，
事件须带 `clientX/clientY`（取 `getBoundingClientRect` 中心）、`view: window`、`bubbles: true`。

- **写入通道的现状**：真实键入（实例 A，2026-09-17）与原型 setter ＋ `input`／`change`（实例 B，2026-09-18）各自整页回读一致；**两者未在同一轮内做过对照**，故不能据此判定「本系统不该走真实输入」——按手册 §3.7.5，仍以真实输入为默认，合成写入只在例外三类时用。实例 C（2026-09-23）追加一条证据：**页面内 `execCommand('insertText')`** 走的是浏览器原生输入事件，React `onChange`（含受控 `maxlength` 截断）会正常触发，121 个字段容器整表回读与数据层三重一致。
- **`Select` 的官方写入入口**：字典下拉在 fiber 树上有一个 `memoizedProps.options` 为数组的节点，其 `stateNode.setValue(opt.value)` 即与真实点选**同一条 React 路径**（值落在同一 state）。批量填表用它可以免开层、免快照取索引，稳定且快；`opt.value` 拿不到时回退 `opt.label`。实例 C 全程用它写完全部下拉（含年月四联、国籍、奖项类型），未出现漏写。
- **级联子字段（必读）**：选到某些选项后会**动态展开一个子字段**，字段容器数当场变化，后面所有同区块字段的 occ 全体后移。实例 C 实测：「编程语言名称」选「其他」→ 该行多出 `请补充`（自由文本 input，占位符「请补充」）。因此**新增/联动后必须重新按 label 普查**，禁止沿用上一轮的 occ；写值前用 `请补充` 这类 **label** 定位，不要用序号。

## 3. 日期类字段

- 起止／就读／获奖时间＝**年、月两个独立下拉**（开始年、开始月、结束年、结束月），按字段内 `.sd-Dropdown-container-1CigZ` 的第 0/1/2/3 个定位。年份选项为纯数字、倒序（2126→1926，共 201 项）；月份为 `1`–`12`。
- 精度只到月，无「日」。按手册 §2.1.6，回读到月即算对齐。
- 有「至今」复选框（实习／项目区块），在读经历不勾（结束时间已填具体月份）。
- 出生日期：`readonly` input，展开后是年月面板（`sd-panal-*`），点选年份 + 月份；值形如 `YYYY-MM (含年龄)`，写入 `input.value`。

## 4. 新增条目

- 「添加」按钮在文档中的序号**会随条目数变化**（每新增一条记录就多一个「删除本条」按钮），固定序号法第二次起即错位。
- 可靠定位：按区块标题（如「实习经历」）元素取 `getBoundingClientRect().top`，在按钮集合中取 top 差值最小且 ≥ −40 的「添加」按钮；「删除本条」同理并可加 nth。
- 点击用 §2 的完整合成事件序列；缺 `pointerdown`/`focus` 时点击可能静默无效，缺 `getBoundingClientRect` 坐标时组件抛错。
- 新增后 React 重排，已填值可能串位或丢失：**每加一条就整页回读一次**，不要在未回读的情况下连续加多条。

## 5. 回读与保存

- 整页回读须同时取 `input/textarea.value` **和** `span.sd-Input-display-value-RwqDy` 文本——下拉与联想字段的值只在后者，只读 value 会全部显示为空，误判为未填。
- ⚠️ **「上传简历」是破坏性操作**（2026-09-18 职位申请表实测，事故级；手册 §2.1.6 的回读核对条款即为此立）：点它会触发 Moka 自动解析 PDF 并**覆盖已填内容**。本轮实测受损面：教育的学院名称与 GPA 被清空；实习由 4 条降至 3 条，且公司名称／职位名称／工作地点／工作职责被换成 PDF 里的写法；项目 2 条全清；自我描述由 488 字变 50 字。附件与表单内容互不干扰（使用者手动上传附件不影响脚本改字段）。**正确顺序是先传附件再填表**；若已填完才上传，必须整表回读逐项修复，不得因「解析已完成」放行。
- 保存：在线简历页底部有「保存」按钮（文本定位，全套合成事件）；**职位申请表无保存按钮**，只有「预览并提交」，未点即未落库（投递动作按手册 §2.1.5 须使用者明确指示）。页面内嵌网易易盾验证码组件，保存/提交环节可能弹出，需用户手动完成。
- 保存判据：手册 §2.1.7 —— 用 `browser_go_to_url` 回同一 URL 重新加载后整页回读（`tab_reload` 在本通道是空操作，不能用）。**注意：职位申请表的页内 state 不落服务端，刷新即全丢**，此时只能用「受损前 dump vs 当前 dump 做 diff」代替刷新回读（见下条）。

### 5.1 被「上传简历」覆盖后的修复流水线（2026-09-23 实例 C 实战定型，必背）

**前提**：填表过程中使用者手动点了「上传简历」→ 自动解析覆盖已填内容。此时**不要刷新页面**（刷新=全丢），按下面四步原地修复：

1. **建受损前基线**：开工时先跑一次整表 dump 存盘（`.workbuddy/_dump_all.js` → `_dump.txt`）。没有基线就没法证明修复完整。
2. **补回被删的条目行**：解析会把添加式区块的条目**删掉几条**（实例 C：实习 4→3、项目 2→1）。先按区块点「添加」把行数补回，**补完再按 label 重新普查 occ**（行数变了，occ 全体后移）。
3. **逐字段回填，文本控件必须"覆盖式"写入**：⚠️ `insertText` 默认是**在光标处插入**；解析已在框里留了值（如已变成 PDF 写法的公司名），若光标停在末尾就会写成「旧值+新值」首尾相接的拼接串（实例 C 实测）。**回填一律先全选再插**：
   ```js
   el.focus(); el.setSelectionRange(0, el.value.length);
   document.execCommand('insertText', false, v);
   ```
   下拉（`setValue`）与日期（年月四联）是替换语义，无此风险；**只有自由文本/textarea 需要覆盖式写入**。
4. **清除解析留下的"幽灵必填错误"**：解析清空字段时会触发整表校验，之后即使把值填回去，页面上仍留着**可见的红色「必填项未填写」**（实测 8 条，字段明明有值）。用 `setValue` 重设、用完整合成事件真实点选**都清不掉**（说明该错误状态不随字段 onChange 复位）。**唯一有效手法：对每个报错控件派发原生 `focusout`** ——
   ```js
   c.querySelector('input').dispatchEvent(new Event('focusout', { bubbles: true }));
   ```
   ⚠️ 派发 `blur` **无效**：React 的 `onBlur` 实际监听原生 `focusout`。实例 C 用这一下把 8 条一次清零（验收：`[class*="Input-message"]` 中含「必填项未填写」的元素数 = 0）。
5. **验收**：再跑一次 dump，与第 1 步基线做 diff。**除"上传位"和本轮主动补填的字段外不应有任何差异**；同时跑必填空项扫描（应为 0）。实例 C 最终 diff 只剩 2 个上传位 + 2 处主动补填。

> 顺带结论：能拿到**简历 PDF 原文**时，用 `pypdf` 抽文本可核对解析结果与数据层是否一致（实例 C 借此发现 PDF 的在校起止月与信息库记录不一致，属数据层待确认项，不是解析 bug）。装法：`<venv>/Scripts/pip.exe install pypdf`。

## 6. 字段清单（两个实例）

### 6.1 在线简历页（实例 A，2026-09-17）

基础信息（姓名／手机／邮箱由账号带入）；
个人信息（性别、工作经验、最高学历、所在地、最近公司、证件类型+证件号码、出生日期）；
求职意向（当前薪资、期望薪资、期望城市）；
工作经历、教育背景（就读时间、学校名称、专业名称、学历）、实习经历（起止时间、公司名称、职位名称、工作职责）、
项目经验（起止时间、项目名称、职责、项目描述、项目中职责）、语言能力（语言类型、掌握程度、听说、读写）、
自我描述、获奖经历（获奖时间、奖项名称）。

应届生：工作经历留空并删除默认空记录（本系统允许删除，删除后保存不报错）。
语言档位按使用者数据层的档位口径填（本页三档：掌握程度／听说／读写），不自行拟定。

### 6.2 职位申请表（实例 B，2026-09-18）

区块顺序：上传 → 个人信息 → 教育背景 → 实习经历 → 项目经验 → 语言能力 → 自我描述 → 获奖经历（+ 底部「更新说明」）。**无**工作经历、求职意向、技能证书、校园经历、大赛经历区块。

- 上传：`上传简历`、`上传照片`（两者带必填星号，附件须使用者手动传，本通道 CLI 无上传命令）。
- 个人信息：姓名、手机号码（区号下拉＋号码输入两段）、邮箱、性别、出生日期（**单个日期 input，值形如 `YYYY/MM`**，非年月分列）、最高学历（由「学历」自动派生、不可直接填）、证件号码（类型下拉＋号码输入两段）、民族、毕业时间（**年＋月两个独立 input**）、招聘信息来源、政治面貌、国籍、生源地（级联地区选择器，展开后「热门地区」快捷标签类名含 `sd-Tag-text`，点「热门地区 北京市」即提交；省份按 A-G／H-K／L-S／T-Z 分组）。
- 教育背景：就读时间（年/月 × 起止四值）、学校名称（远程联想）、学院名称（普通输入）、专业名称（远程联想）、学历、GPA（得分/总分，普通输入）。
- 实习经历：起止时间（四值＋「至今」）、公司名称、职位名称、工作地点、工作职责（textarea）。
- 项目经验：起止时间、项目名称、职责（单行 input）、项目描述（textarea）、项目中职责（textarea）。注意「起止时间」与实习区块同名，**须按字段全局索引区分**。
- 语言能力：语言类型（**自由文本输入，无候选下拉**，直接写值即可）、掌握程度（字典下拉）。
- 自我描述：单条 textarea。
- 获奖经历：获奖时间（年＋月两值）、奖项名称（**该行只有名称一个输入框、无描述框**；数据层里带描述的条目须把描述并入名称）。

### 6.3 职位申请表 · 全字段长版（实例 C，2026-09-23，ZTE `applyFormId=55172`）

⚠️ 实例 C 与实例 B **同名同源却是两套模板**：实例 C 的区块远多于实例 B，**且多出的区块里有 3 个必填**。开工前必须按 `[data-nav-id]` 现普查区块清单，不要照抄任一实例的区块表。

实例 C 区块顺序（`data-nav-id`）：
`block-applyInfo`（申请信息：意向工作城市*／推荐码）→ `block-uploadInfo`（上传照片*／上传简历／上传附件）→ `block-basicInfo`（个人信息 24 字段）→ `block-educationInfo` → `block-32783`（校园工作经历）→ `block-practiceInfo`（实习经历）→ `block-projectInfo`（项目经验）→ `block-34807`（论文）→ `block-32781`（竞赛）→ `block-32786`（荣誉奖项含奖学金）→ `block-32782`（专利）→ `block-30698`（软件著作权）→ `block-30701`（编程语言能力）→ `block-30706`（外语能力）→ `block-32787`（技能证书）→ `block-selfDescription`（自我描述）→ `block-45926`（隐私声明·确认声明*）→ `block-updateAccountResume`（同步更新在线简历）→ `block-privacyStatement`（授权文本《隐私协议》）。底部仍只有「预览并提交」，无「保存」。

**实例 C 专属要点（数据层字段名 → 控件 → 值口径）**
- 个人信息：多出「最高学历院校所在城市」「最近毕业专业」「意向岗位 1/2」「是否接受其他岗位/工作地调剂」「意向工作地 1/2」「兴趣爱好」「出生国家」「其他国籍」「永久居留权国家」「以上哪个是您最近取得的永久居留权国家*」。**bool 类（是否接受调剂／是否最高学历）模型存 `1`（是）/`0`（否），不是「是/否」字符串**——回读见 `1` 不要误判为错误。
- ⚠️ **「以上哪个是您最近取得的永久居留权国家」是必填**（国家全量下拉，含「中国」）。国籍＝中国、无境外永居时此栏无正解：留空**会在必填校验上挂**，实测按「中国」填可过校验且与国际/出生国家自洽；填完须在汇报里点明这一条属推断，交使用者定夺。
- 教育背景：硕士条与本科条各 14 字段，含「实验室名称／导师姓名／研究方向／成绩排名／GPA 分数／GPA 总分」；**「研究方向」是必填**，数据层无此项时按专业取最接近的通用表述，用词保守。成绩排名为固定档位 `TOP 1%…TOP 50%／其它`，按手册 §2.2 第 3 条「宁宽勿假」取**真实涵盖真实值**的档（如真实前 25% 选 `TOP 30%`）。「GPA 分数／总分」是数字框，按数据层的绩点口径分两栏填。
- 实习经历：多出**「实习使用技能」自由文本**（易漏，非必填）。数据层无逐条技能时，按各条经历描述里**确有出现**的技能归纳（如某技能只在某一段经历里出现，就只写在那一段），不要整表复制同一串。
- 竞赛（`block-32781`）：参赛时间（四值区间）、竞赛名称、竞赛类型（字典，含「国际级」）、竞赛成绩（自由文本，写 `Honorable Mention` 这类原名）、竞赛描述。

**必填空项扫描法（本轮最高效的一步，建议标准化）**
先按 `reqOf`（标题含 `*` 或子节点类名含 `required`）筛出全部必填容器，再对每个容器用 fiber 上的 `_get_()` 取值判空（`''`/`null`/`[]`/`{}` 视为空），一次性输出「必填但为空」清单。实例 C 收尾扫出 4 项（永久居留权国家、本科是否最高学历、本科成绩排名、确认声明），比逐块肉眼核对快且不漏。**注意**：`_get_()` 读 bool 字段返回 `0`，`0` 是有效值不是空，判空不要用 falsy。

**无论文的处理**：`block-34807` 论文、`block-32782` 专利、`block-30698` 软件著作权三个添加式区块，本次数据层无对应记录，**保持空**（不新增「无」条目——空区块在 Moka 属正常，新增名为「无」的条目反而难看）。若使用者要求写「无」，再新增一条名称填「无」。
