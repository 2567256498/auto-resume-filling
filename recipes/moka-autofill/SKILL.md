# Moka 校招简历填写配方（moka-autofill）

适用：Moka 校招候选人端**两类页面**——① 在线简历页 `app.mokahr.com/campus-recruitment/<机构>/<id>#/candidateHome/resume`；② 职位申请表 `app.mokahr.com/campus-recruitment/<机构>/<id>#/job/<jobId>/apply?applyFormId=<id>`。两者字段集与按钮结构都不同（见 §1 末条、§5、§6），套用前先判是哪一类。
首次实战：2026-09-17（投递台账序号 32）。现场侦察重建，只记本系统结构与手法；通用纪律见本手册。

> **通道 = QQ 浏览器**（命令映射见手册 §三）。
> **本通道已复现的动作**：判框架、页面内 JS（完整合成事件序列开层／点选、原型 setter 写入）、`browser_input_text --index` 真实键入、`browser_go_to_url` 真重载均已在本系统跑通；**未复现**的是真实点击开层与 iframe 穿透（开层走事件序列，本配方不依赖二者）。

## 1. 框架与 DOM 骨架

- 框架：React（旧版，元素上挂 `__reactInternalInstance$<hash>` / `__reactEventHandlers$<hash>`），组件为 Moka 自研 `sd-*` 系（非 antd、非 element-ui）。
- 字段容器：`.apply-field-Q2iJ7AtQGX`，标题在子 `.title-IWWQ0Xa4L7`；区块（教育背景／实习经历等）内字段按 DOM 顺序排列，同名标题按出现次序（occ）区分。
- 区块添加按钮：文案「添加」；每条记录另有「删除本条」。
- **页面类型决定按钮结构**：① 在线简历页（实例 A）底部有「保存」按钮，保存＝整页提交，不做逐条保存；② 职位申请表（实例 B）**全页无「保存」按钮**，只有一个「预览并提交」，另有左侧区块导航与底部「更新说明：同步更新在线简历」勾选——此类页面填完**无法自查落库**，只能进预览页。

## 2. 四类控件与写入通道

| 控件 | 识别 | 写入方式 | 值落在哪 |
|---|---|---|---|
| 普通文本输入 | `input`，`maxlength=255`（姓名／所在地／最近公司／证件号码／当前薪资／期望薪资／期望城市／公司名称／职位名称／项目名称／职责／语言类型／奖项名称） | 真实键入：取 snapshot 编码索引 → `browser_input_text --index <idx> --text <值>`（索引每次会变，键入前重取 snapshot） | `input.value` |
| 多行文本 | `textarea`（工作职责／项目描述／项目中职责／自我描述），无 maxlength | 同上；文本内含 `\n` 可真实换行，保存回读后换行保留 | `textarea.value` |
| 字典下拉 | 字段内含 `.sd-Dropdown-container-1CigZ`，`input` 只读展示（性别／工作经验／最高学历／学历／掌握程度／听说／读写／年／月） | **只能点选**：点 input 展开 → 在字段容器内找可见 `.sd-Select-menu-36GwS` → 点 `.sd-Select-common-item-3YCIH` 中文本匹配项 | `span.sd-Input-display-value-RwqDy`（`input.value` 恒为空） |
| 远程联想 | 同下拉结构但可键入（学校名称／专业名称） | 键入后**必须点选候选项**；仅键入不入 React state，后续任何 re-render 会静默清空 | `span.sd-Input-display-value-RwqDy` |

开层与点选都要派发完整合成事件序列（缺一不开层）：
`pointerover → mouseover → pointerdown → mousedown → focus → mouseup → pointerup → click`，
事件须带 `clientX/clientY`（取 `getBoundingClientRect` 中心）、`view: window`、`bubbles: true`。

- **写入通道的现状**：真实键入（实例 A，2026-09-17）与原型 setter ＋ `input`／`change`（实例 B，2026-09-18）各自整页回读一致；**两者未在同一轮内做过对照**，故不能据此判定「本系统不该走真实输入」——按手册 §3.7.5，仍以真实输入为默认，合成写入只在例外三类时用。

## 3. 日期类字段

- 起止／就读／获奖时间＝**年、月两个独立下拉**（开始年、开始月、结束年、结束月），按字段内 `.sd-Dropdown-container-1CigZ` 的第 0/1/2/3 个定位。年份选项为纯数字、倒序（2126→1926，共 201 项）；月份为 `1`–`12`。
- 精度只到月，无「日」。按手册 §2.1.6，回读到月即算对齐。
- 有「至今」复选框（实习／项目区块），在读经历不勾（结束时间已填具体月份）。
- 出生日期：`readonly` input，展开后是年月面板（`sd-panal-*`），点选年份 + 月份；值形如 `YYYY-MM (含年龄)`，写入 `input.value`。

## 4. 新增条目

- 「添加」按钮在文档中的序号**会随条目数变化**（每新增一条记录就多一个「删除本条」按钮），固定序号法第二次起即错位。
- 可靠定位：按区块标题（如「实习经历」）元素取 `getBoundingClientRect().top`，在按钮集合中取 top 差值最小且 ≥ −40 的「添加」按钮；「删除本条」同理并可加 nth。
- 点击用 §2 的完整合成事件序列；缺 `pointerdown`/`focus` 时点击可能静默无效，缺 `getBoundingClientRect` 坐标时组件抛错。
- 新增后 React 重排，已填值可能串位或丢失：**每加一条就整页回读一次**，不要在未回读的情况下连续加多条。

## 5. 回读与保存

- 整页回读须同时取 `input/textarea.value` **和** `span.sd-Input-display-value-RwqDy` 文本——下拉与联想字段的值只在后者，只读 value 会全部显示为空，误判为未填。
- ⚠️ **「上传简历」是破坏性操作**（2026-09-18 职位申请表实测，事故级；手册 §2.1.6 的回读核对条款即为此立）：点它会触发 Moka 自动解析 PDF 并**覆盖已填内容**。本轮实测受损面：教育的学院名称与 GPA 被清空；实习由 4 条降至 3 条，且公司名称／职位名称／工作地点／工作职责被换成 PDF 里的写法；项目 2 条全清；自我描述由 488 字变 50 字。附件与表单内容互不干扰（使用者手动上传附件不影响脚本改字段）。**正确顺序是先传附件再填表**；若已填完才上传，必须整表回读逐项修复，不得因「解析已完成」放行。
- 保存：在线简历页底部有「保存」按钮（文本定位，全套合成事件）；**职位申请表无保存按钮**，只有「预览并提交」，未点即未落库（投递动作按手册 §2.1.5 须使用者明确指示）。页面内嵌网易易盾验证码组件，保存/提交环节可能弹出，需用户手动完成。
- 保存判据：手册 §2.1.7 —— 用 `browser_go_to_url` 回同一 URL 重新加载后整页回读（`tab_reload` 在本通道是空操作，不能用）。

## 6. 字段清单（两个实例）

### 6.1 在线简历页（实例 A，2026-09-17）

基础信息（姓名／手机／邮箱由账号带入）；
个人信息（性别、工作经验、最高学历、所在地、最近公司、证件类型+证件号码、出生日期）；
求职意向（当前薪资、期望薪资、期望城市）；
工作经历、教育背景（就读时间、学校名称、专业名称、学历）、实习经历（起止时间、公司名称、职位名称、工作职责）、
项目经验（起止时间、项目名称、职责、项目描述、项目中职责）、语言能力（语言类型、掌握程度、听说、读写）、
自我描述、获奖经历（获奖时间、奖项名称）。

应届生：工作经历留空并删除默认空记录（本系统允许删除，删除后保存不报错）。
语言档位按使用者数据层的档位口径填（本页三档：掌握程度／听说／读写），不自行拟定。

### 6.2 职位申请表（实例 B，2026-09-18）

区块顺序：上传 → 个人信息 → 教育背景 → 实习经历 → 项目经验 → 语言能力 → 自我描述 → 获奖经历（+ 底部「更新说明」）。**无**工作经历、求职意向、技能证书、校园经历、大赛经历区块。

- 上传：`上传简历`、`上传照片`（两者带必填星号，附件须使用者手动传，本通道 CLI 无上传命令）。
- 个人信息：姓名、手机号码（区号下拉＋号码输入两段）、邮箱、性别、出生日期（**单个日期 input，值形如 `YYYY/MM`**，非年月分列）、最高学历（由「学历」自动派生、不可直接填）、证件号码（类型下拉＋号码输入两段）、民族、毕业时间（**年＋月两个独立 input**）、招聘信息来源、政治面貌、国籍、生源地（级联地区选择器，展开后「热门地区」快捷标签类名含 `sd-Tag-text`，点「热门地区 北京市」即提交；省份按 A-G／H-K／L-S／T-Z 分组）。
- 教育背景：就读时间（年/月 × 起止四值）、学校名称（远程联想）、学院名称（普通输入）、专业名称（远程联想）、学历、GPA（得分/总分，普通输入）。
- 实习经历：起止时间（四值＋「至今」）、公司名称、职位名称、工作地点、工作职责（textarea）。
- 项目经验：起止时间、项目名称、职责（单行 input）、项目描述（textarea）、项目中职责（textarea）。注意「起止时间」与实习区块同名，**须按字段全局索引区分**。
- 语言能力：语言类型（**自由文本输入，无候选下拉**，直接写值即可）、掌握程度（字典下拉）。
- 自我描述：单条 textarea。
- 获奖经历：获奖时间（年＋月两值）、奖项名称（**该行只有名称一个输入框、无描述框**；数据层里带描述的条目须把描述并入名称）。
