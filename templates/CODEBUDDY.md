# 项目级要求（简历网申填写）

> **本文件是本报项目级要求。** 对本工作区（`__PROJECT_DIR__`）发起的全部会话生效，正文每一条都是硬性要求，不是背景说明。
> 本文件由简历网申填写封装体的初始化脚本生成（`__PACKAGE_NAME__` `__PACKAGE_VERSION__`），生成时间 `__GENERATED_AT__`。
>
> **效力顺序（冲突时由上到下）**：① 用户当场指令 → ② 用户级全局要求（`__USER_RULES_DIR__`）→ ③ 本文件 → ④ 通道文件 `__CHANNEL_FILE__`（怎么操作浏览器；本环境若无该文件，改以封装体手册 §三 为准）→ ⑤ 配方 skill `__RECIPES_DIR__/<名>-autofill/`（怎么填某个具体系统）→ ⑥ 经验台账／变更档案（只提供判定依据，本身不产生要求）。**封装体 `__PACKAGE_DIR__` 不在效力链内**——它是本项目配方的去个人化镜像，只读不反向（§〇.4）。下级与上级冲突一律按上级；数据口径以数据层 `__DATA_DIR__` 为准，库与任何文件冲突时停下来问用户。

## 〇、资产归属与边界

1. **取数单真源**：数据层 `__DATA_DIR__`——这是取值与事实的唯一来源，不建副本、不设缓存。投递台账只追加、不重排、不删行、不跳号（序号是轮次锚点，一断即无法修复）。
2. **本项目专属**：配方 skill、通道文件与经验台账落在 `__SKILLS_DIR__`。
3. **不看不碰**：本任务范围外的目录与文件（见 §〇.5）一律不读取、不改动、不覆盖。**引用非本通道来源的经验时**，只允许引入**与浏览器通道无关的页面／系统层事实**（字段长度上限、保存接口行为、必填口径等），且须标注「未在本通道复现」。
4. **封装体＝随包的成品包**：`__PACKAGE_DIR__`（使用说明 `README.md` ＋ 手册 ＋ `recipes/` ＋ `scripts/`）是**可供移交的成品包**；其 `recipes/` 下配方复制到本项目配方目录 `__RECIPES_DIR__/<名>-autofill/`，**此后以本项目这份为唯一活跃源头**（填写手法一律以它为准，遇新系统仍现场重建，落点见 §六）。**同步方向单向**：本项目配方／通道口径有实质更新后，同步一次进包（去个人化——清掉人名与本机路径，把本项目文件引用换算成包内手册节号），并跑一次包内机械校验，退出码 0 才算同步完成；**不用包内旧文覆盖本项目**，包内手册与配方不作本项目的要求或手法来源。
5. **禁止触碰清单**：`__FORBIDDEN_PATHS__`。

## 一、数据口径

- 简历事实数据、定稿文案与各系统表单口径统一在数据层 `__DATA_DIR__`（若分主数据文件与字段映射文件，主数据存事实与定稿文本，字段映射存招聘系统字段取值、附件与照片路径、问卷类取值）。文件间冲突时列出差异请用户确认，不得自行取舍。
- **新信息必须同步回权威文件**：任何会话中得到的新事实、新口径（学号、成绩、日期、联系人、证书等），只要与库内旧信息不同或库内没有，必须同步更新到数据层，不得只记在对话里或只填在某个招聘系统里。操作顺序：先确认新信息属实 → 更新权威库 → 再用权威库数据填表。
- **文案类不自动固化**：职业目标、求职动机等按目标公司现场撰写的文案，除非用户明确要求，不写入数据层；需要时现场撰写并交用户确认。
- **权威库只存数据本身，不存版本变更历史**：changelog／version／更新记录类元信息一律不写入主数据文件，变更过程留在对话里；填写／投递过程记录只进投递台账。
- **更新权威库前先列单审核**：拟更新数据层文件时，先列清楚改哪些字段、改前改后是什么，用户审核同意后再统一修改；不边发现边改、不边填表边改库。

## 二、行为硬规则（违反即事故）

1. **绝不编造**：没有事实依据的字段宁可留空或问用户。必填但库里没有 → 问用户；用户不在就留白并明确告知"此项待你手动填"。错填比漏填严重。
2. **带星号（*）即必填**：直接对照数据源取数，不留空试探校验。
3. **简历附件绝不自行搜索**：PDF／成绩单／作品集版本更新频繁，必须问用户要绝对路径。
4. **批量填表前先侦察**：动手前先跑三步——判框架 → 选写入通道 → 扫字段清单（tag／必填星号／计数器上限／重复 DOM 树／动态增删字段），给出一句话计划再执行。动态增删字段的表单一律按行 label 定位，禁用序号定位（一次重渲染即全部错位）。
5. **不擅自投递 ＋ 投递台账**：任何「投递／提交／发送」按钮必须用户明确指示后才可点击。投递台账记录生命周期（列：序号／投递日期／公司／岗位／投递渠道／状态／备注）：填写完成并回读核对后即追加一行，岗位未定写「待用户补录」、状态用「暂存未提交」；正式投递后问用户投了什么岗位，更新该行状态——只以用户答复为准，不从页面推断。**本表为单真源、只追加**：不重排、不删行、不跳号，也不批量整理格式（实测：改动会重写整表并改变单元格类型）。
6. **填完必须回读核对**：保存后刷新／回读页面，逐项对照数据源检查，汇报"已核对 N 项，修正 M 项"。「上传简历自动解析」只作脚手架：解析会清空已填字段、把日期写回废弃口径、把无关内容填进错误区块，用后必须整表回读、逐项修复并把长文本换回定稿，不得因「解析已完成」跳过核对。日期类字段回读必须核对到「日」，控件只到月时按当月口径记录。**核对必须双向**：除「表→库」逐字段比对外，还要做「库→表」覆盖清点——按库内条目清单（实习／校园／项目／奖项／家庭／证书／语言等）逐桶确认是否已在表中落位；表单无对应区块时按经历归类口径就近归位或问用户，不得默认丢弃。
7. **保存成功判据**：以整页刷新后数据仍在为准，表单打开不等于保存成功；单条目操作一气呵成，保存按钮只点一次（双击会触发重复提交弄掉会话）。多区块逐条目即时保存，页面丢失或黑屏时损失以单条为限。
8. **先填后问（缺失数据最后批量询问）**：已有完整信息的字段／区块全部先填并保存；缺数据的跳过并记录（该区块因必填缺失无法保存时：表单保持打开，不点取消、不刷新页面，避免已填内容丢失）；全部可填项处理完后，把缺失数据一次性汇总询问，得到答复后回填补存。不为个别缺失字段阻塞整体进度，也不边填边频繁打断用户。
9. **不维护进度 md**：本工作区不创建、不更新进度记录类 md 文件；填报进度与交接内容在对话里直接汇报。
10. **整块完成才刷新、打断不续跑**：验证性刷新按「整块任务」粒度做（一轮填写完成后刷新一次），不在条目之间反复刷新；用户中途打断的任务不自动恢复续跑，等用户明确指示。
11. **本项目的术语不是通用词义，动手前先查定义**：下列词在本文件或任务手册中有专有定义，**执行前必须先读定义处，不得按字面理解动手**——「经验复核」「轮／已复核轮／未复核轮」「待验」「登记轮／关联次数／空转」「漂移／回摆」「固化率」「十一步收尾流程」「判据对照」「配方」「台账／变更档案」。**本项目的定义处有两个**：本文件 §四（经验机制）与任务手册 §5.1–§5.3（收尾流程与回写顺序）；两处都查不到才按字面理解并在汇报里说明。**推论**：用户点名某个 skill 或手册时，先读该手册再动手。

## 三、内容填报硬规则

> **本节通则与专属口径的分界**：下列各条是**本项目的通用填报口径**；"某个具体字段该写成什么样"属专属取值，由数据层提供（§一）。数据层缺失时按本节通则执行。

1. **单位名称栏只填公司规范全称**，不拼接部门岗位。有独立部门／职位字段则各自单独填；都没有 → 部门岗位写进工作描述开头；只有职位栏 → 部门并入职位栏。
2. **工作描述／主要业绩**：写前先读页面字数计数器确认上限（各系统不同，勿凭记忆），写到接近上限；一律编号分行（1. 2. 3.）且**分点之间用真实换行、各占一行，不用空格**（空格分隔会被部分系统在保存回读时吞掉、造成两点粘连）；超限时按整条删除压长度，绝不在句中硬截断；描述内不重复单位／部门题头。
3. **证书／奖项只写规范名称**，不展开描述、不写颁发单位／分项成绩；仅表单强制必填时从简补写。证书栏为自由文本输入（非逐条选择）时同类合并。
4. **英语档位四档制**：读写＝精通，听说＝熟练；总体／掌握程度跟读写填「精通」。档位名不同按同逻辑映射。
5. **经历归类**：非实习经历里，班干部任职放「在校职务／学生干部」或「校园经历」区块，**不入「项目经历」**；除此之外的非实习经历均可放「项目经历」或「校园经历」；应届生「工作经历」留空。
6. **成绩排名等分档字段**：选能真实涵盖真实值的最宽一档，宁宽勿假——真实值必须确实落在所选档位内；档位不覆盖真实值时改选「其他」或留空（非必填），绝不选不覆盖的档位。
7. **主修课程罗列规则**：列核心课程＋成绩时高分在前，低于阈值分的不放（除非表单明确要求列出全部课程）；挑代表课 10–15 门，不硬塞全部。同一课程跨学期带序号（如某课-1、某课-2）合并为课程名列出，不逐学期罗列序号。
8. **自我评价**：直接取用数据层的定稿版，不得自行改写；按表单字数上限选用对应版本。
9. **教育经历含高中必填**：凡表单要求填至高中／中专层级（含「如有」可选项）时，必须填写高中经历，不得留空；仅当表单明确排除高中时不填。表单学校库无中学时用上传组件的「手动添加」入口填学校全称，学科门类无对应项时选「其他」并在补充框填文理分科。
10. **严格遵从条目要求填写**：每个字段只填条目明确要求的内容，条目未要求的信息一律不附加——字段未要求成绩就只列课程名不写分数，未要求描述就不写描述，未要求时间就不写时间；通用规则里的附加元素仅在条目明确要求时出现。
11. **初步完成后检查写入内容和标签是否适配与正确**：逐项核对内容与标签是否对应、填写是否正确，发现错位或错填当场改正，再保存。
12. **无奖项栏位时的归属**：表单没有「奖励／荣誉」栏时，奖项并入「证书」栏填写；已在别处单独落位的大赛经历不重复填。

## 四、经验固化与复核

> **本节是「经验复核」等术语的定义处之一**（另一处在任务手册 §5.1–§5.3）。完整规则以经验台账待验节首所列为准，本条不重复。

- ① **落点与判定依据**：经验条目要有判定依据、可被剔除。**台账** `__LEDGER_FILE__`（当前态：待验＋最近一轮结论，行格式「条目 | 域 | 登记轮 | 关联次数 | 固化 | 待验原因 | 触发条件」）；**变更档案** `__CHANGELOG_FILE__`（落点登记簿＋事件流：新增/修订/删除/降级/拆分/清出/回摆＋依据），用于核查同一条目是否反复进出。**触发点**：每次任务收尾，或单次会话出现 ≥3 次「踩坑→修正」回路。**分流与门槛**：取值类直接进数据层；手法类首见入待验、≥2 次复现或一次事故背书才入册。**落点**——跨项目通用进用户级全局要求，本域内通用进本文件或通道文件，单系统手法进 `__RECIPES_DIR__/<名>-autofill/SKILL.md`，取值类进数据层；首见手法类先入台账【待验】并标注拟入层级，达标上提后在该行备注写明落点并从待验表清出，不入册的写明原因。
- ② **条目 ID（一切计数与核查的身份基准）**：每条经验发一个 ID，形如 `<域>#<主题键>`——域取「要求／通道／配方／数据／台账／封装体／机制」之一，主题键是 2–8 字的话题名。**ID 不含落点路径、一经发出不再更改**：条目从待验上提进配方、或换了落点文件，ID 不变，只改登记簿里的「当前落点」。变更档案事件流第 2 格即 ID；同一话题的历次变动共用一个 ID，这是判断「反复进出」的唯一依据。
- ③ **登记簿（做分母）与双向对账**：变更档案开头设「落点登记簿」，一行一个 ID——`条目 ID｜类｜当前落点｜状态｜首登日期｜事件数｜最近事件日期`（**「类」取 条目／部件**，域已含在 ID 前缀里、不单列），状态取 在册／已删／已并入。**悬空 ID** ＝登记簿里有、事件流里没有任何该 ID 的行；**未登记 ID** ＝事件流里有、登记簿里没有。两者都算结构异常，当场补齐，机械校验也查这一项。
- ④ **抖动处置（两条判据）**：**漂移**——同一 ID 在**最近 5 个已复核轮**内发生 ≥3 次变动（新增／修订／删除／降级／清出／回摆都算）→ 判定该条目定义不清，只能**降级**（红线→手法→数据层）或**拆分**（只留触发条件，具体做法挪到数据层），不再反复改文字。**排除项：机制类 ID 的正常迭代不计入漂移**——「校验器／模板／轮次基准／休眠归档／说明文档」等**描述机制部件本身**的 ID，其变动多为部件被正常使用与改进（改校验脚本、追加轮次行、执行池满归档），不是「定义不清」，故只统计、不触发处置；判据只对**经验条目类 ID** 生效。归属看不出的，按「该 ID 描述的是判断点还是部件」判。**回摆**——同一 ID 出现过「删除／清出／撤回」之后又被「新增」→ **单次即报**，它比漂移更硬，说明该条此前被误删或门槛判断反复，须回头查当时依据并把结论写进该 ID 备注。**回摆判据不限窗口**。**证伪单列强信号**：同一 ID 出现 ≥2 次证伪即判定义不清，按漂移同等处置（降级或拆分），不必等到 3 次变动。
- ⑤ **固化率（经验是否已固化的指标）**：`固化率 ＝ 窗口内零变动的 ID 数 ÷ 登记簿中状态为「在册」且「类＝条目」的 ID 数`，窗口＝最近 5 个已复核轮；零变动＝该窗口内事件流没有任何该 ID 的行。**分母只计「条目」类**——登记簿另设「类」列，`类＝部件` 的机制类 ID（校验器／模板／轮次基准／休眠归档／说明文档…）其变动属部件被正常使用与改进、不代表定义不清，与漂移同口径排除在外，只统计不参与分母（判据是语义：描述**部件**还是**判断点**，登记簿写死结论、不硬编码名单）。**不要拿发生量当成效**——事件多说明还在改，不算固化。
- ⑥ **按 ID 折叠**：同一 ID 的事件行超过 4 条时折叠——保留最近 2 条原始行＋1 条汇总行（写明累计次数与区间），其余原始行搬入「留档区 → 已折叠事件（按 ID）」**只移不删**；汇总行的依据只留一句，细节指向留档区。
- ⑦ **轮次计数与自我淘汰**：**轮次计数**——轮＝一次任务收尾的经验复核，填报任务以投递台账行序号标识、非填报任务以「日期-简称」标识，登记在台账「轮次基准」清单，**若本轮做了经验复核**才追加该轮行，同一会话只计一轮；**未复核轮**＝台账有行但本项目未做复核的行，自动判定、不计入任何计数。待验条目带「域＋登记轮＋关联次数＋固化」四列：**域分三档并决定到期阈值**——流程域（与具体站点无关的操作或机制事实）4／框架域（第三方框架层行为，换站点仍可复验）6／系统域（某招聘系统的自有组件、字段与业务口径）10；空转＝当前轮号−登记轮（现算不维护），关联次数＝自登记轮后该域再度出现的已复核轮数（信息性指标，不决定到期）。**到期＝空转 ≥ 域阈值 且 固化＝未固化 → 降级入变更档案「休眠区」**（退出计数，**不是删除**，正文整行搬入）；**固化豁免**——已达门槛的条目不参与到期，且不得跨轮留存（要么并入清出、要么经使用者驳回后改回未固化）。**第二支到期判据「反复不复现」型**——关联次数 ≥2 且 空转 ≥ 域阈值 且 未固化 → 同样降级入休眠区并标「反复不复现」，该型**不再被唤醒**（域再现也不回表）、只能被清出。**唤醒在到期之后**：同一收尾内本轮该域出现的条目即使空转到期也不休眠，池满归档同样**跳过本轮该域出现的行**。**休眠区不得只进不出**：该域再现 → 唤醒回表并关联 +1（「反复不复现」者除外）；已被配方正文覆盖 → 转「已删除／清出条目」区并记事件。**到期处置优先于 ⑧ 的「判断不了不删」**，后者仅适用于未到期条目。**池满不删有效条目**：待验表 **>20 行**时把空转最大者降级入休眠区，直到不超限；基准**满 20 轮**与档案指标节**最近 3 轮**分别触发折叠。**行内部分固化**：一行含多条观察时，某条命中或证伪即就地删该条观察、行保留，行内清空才整行清出。**本轮身份自检**：填报轮的结论节标题必须点出本轮系统名（该轮行投递渠道列的平台串至少一个出现在标题或基准名里）。**机制演进**：改判据／阈值／结构须先列依据清单并报使用者批准，依据与批准记入档案事件行；域阈值每满 20 轮复看；拆分出的判断点留父链（「拆分自 X」）；改数值规则须同步包内校验脚本 `__PACKAGE_DIR__/scripts/verify-package.py` 里集中维护的机制数值表（第九段末的「模板机制数值 ↔ 校验判据一致」就是查这个的）。**冻结**：本机制结构冻结，除非再出事故级反例（错填／数据被覆盖／会话丢失级）。**清出前先对账 skill 正文**（忽略此条是本类最常见的脱节）；台账单元格禁写**竖线**。**收尾流程**按台账待验节首所列**十一步**执行（第 6 步＝改条文前先查该 ID 的变动史）；台账只留待验与最近一轮结论、档案每轮折叠。完整规则以台账待验节首为准，本条不重复。
- ⑧ **证伪的处置**：证伪的当场改或删，判断不了的标【待验】不删；删红线条目先列单说明依据。

## 五、浏览器通道

> 本项目的通道特征、可用性前提、命令面与故障处置，**以通道文件 `__CHANNEL_FILE__` 与任务手册 §三 为准**；本节只列本项目强制的行为面，不复制命令表。

1. **通道可用性有前提**：浏览器必须由使用者在自己的桌面会话中、带内置扩展参数启动并保持。**「浏览器开着」≠「通道可用」**；自行拉起的浏览器活不过当前命令。接续任务前先看启动器日志是否出现「客户端已连接」，不满足就**停下请使用者启动，不要自行反复拉起**。
2. **每个任务显式开会话、收尾关会话**：一段对话只铸造一次会话 ID，整段复用；会话绑定命令必须显式带该 ID。
3. **接续任务先建组、再核对落点，绝不直接下命令**：页面级命令在无会话组时会落到**浏览器当前激活标签**（很可能就是用户自己的页面）。动手前先跑一次**只读**读取当前地址核对落点，非目标页就停下报告、不得写入。
4. **只动本任务的目标页**：用户自己的标签页（自用页、其他系统页、已登录页）一律不碰——不点击、不滚动、不提交、不改 DOM。找不到目标页就问用户，绝不自行猜地址导航，也不新开页面顶替用户正在填的页面。
5. **提交／保存类按钮一次点击一条记录**；任何「投递／提交／发送」按钮非用户明确指示不点（§二.5）。
6. **注入脚本一律整体 try/catch**，出错以字符串返回，不让异常逃出；需要多段等待就拆成多次调用。
7. **命令报错不等于未执行**：先回读页面状态确认，不盲目重跑写入——重复提交会弄掉会话。
8. **定位不确定不用点击试探**：改用页面内 JS 派发 DOM 事件；尤其禁止对提交／保存类按钮反复试探点击。
9. **文本字段默认走真实输入；例外按控件类型分流**：字段可键入时默认走真实输入——真实输入失败是**显性**的（回读立刻发现），合成写入失败是**隐性**的（回读都有值、保存后整页回读才归零）。例外：隐藏／组件托管控件走组件状态写入或键盘路径；远程联想字段走下拉选择配方；本通道真实输入实测不可用时才降级用合成写入做草稿，且保存回读发现缺失一律改真实输入重写再复验。**无论走哪条，落库判据统一是「保存后整页回读」**（§二.7）。
10. **动手前先判框架、按框架选数据入口**：用一次页面求值读出判据（React `__react*`／Vue2 `__vue__`／Vue3 `__vueParentComponent`／Angular `window.angular`），并统计字段容器数量。非文本控件（日期／下拉／单选／复选）一律优先找组件实例的数据入口直调；只有无框架托管的原生表单／jQuery 字段才用 value setter ＋ 派发事件。**不模拟鼠标交互**——自定义下拉的选项常在 body 级 portal 动态渲染，跨调用即关闭。
11. **读值必须读框架内部状态**，不读 `input.value`（production 构建会剥掉调试指针时，判据退化为「保存后整页回读」，并把该现象记入待验）；否则会把"页面看着有值、框架里却是空的"假填误判为已填。
12. **分批写入，每批 5–8 个字段**：单次写入字段过多易触发执行超时；超时不代表未执行，先回读确认再决定是否重做。

## 六、表单操作配方与分层

**封装体是随包的成品包**（见 §〇.4）：本项目配方有实质更新后同步一次进包，包内手册与配方不作本项目的要求或手法来源。**存量配方在本项目** `__RECIPES_DIR__`；引用一律指向本项目文件；遇新系统仍走**现场侦察、现场重建**。三层落点全部落在**本项目自持**位置：

1. **通道层**——浏览器怎么操作（会话模型、命令、定位三档、写入纪律、页面安全）：`__CHANNEL_FILE__`；本文件 §五 是它的硬性要求面。
2. **框架层／系统层**——遇到具体系统时先侦察判框架，手法写入或更新 `__RECIPES_DIR__/<名>-autofill/SKILL.md`；判断点 ≥5 条且不跨系统复用时才单独立文件，一次性手法就地写进经验台账，不立文件。
3. **数据层**——字段取值与口径在数据层，不放操作配方。

**已识别系统的判据对照**：见任务手册 §4.7（侦察时按识别特征判框架归属；表内是**页面层事实**，与通道无关、可直接复用，但其上衍生的机制描述仍须在本通道实测后回写结论）。

**归属判据**：下次遇到同类系统还能用→框架层；只在这一个系统能用→系统层；只是取值→数据层。**来自其他浏览器通道的机制描述一律按【待实测】对待**，在本通道首次使用时实测，用一次即把结论回写本项目落点与台账。

## 七、要求文件与经验文件的维护

1. **改前重读磁盘版**：本工作区可能多会话并行——动手前重读目标文件并看 mtime／字节数，判断是否刚落过他会话的改动；以磁盘当前内容为编辑基准，不覆盖他人改动，不拿自己上一轮的读数判断文件状态。
2. **生效条件与容量**：本文件由进程启动时加载并缓存，改后需重启会话才生效；正文上限 **__MAX_BYTES__** 字节，超限整份失效——新增条目前先核对合计字节数，宁可归并或下沉到 skill，不逼近上限。
3. **每次任务收尾跑一次机械校验**：`python "__PACKAGE_DIR__/scripts/verify-package.py" --ledger "__LEDGER_FILE__"`——脚本随封装体走（封装体目录见 §〇.4）。带 `--ledger` 时追加**运行态**校验（第十段：轮次基准／待验表／到期／池量／登记簿对账），不带则只校封装体自身自洽（九段）。**exit 1 即结构异常，先修结构再收工**。本环境若另有自建校验器，可一并跑，两者不冲突。
4. **三层分工**：硬性要求写进要求文件（用户级全局要求／本文件／通道文件／配方 skill），判定依据写进经验台账与变更档案（§四），事实与归属写进记忆文件；要求本身变了就改要求文件，不靠记忆或台账兜底。
