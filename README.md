# 简历网申填写 · 使用说明

这份包用于**网申／招聘表单填写**：把使用者资料库里的简历事实，填到招聘网站的表单上，填全、填对、可追溯。

本文件是上手用的简版。**完整要求、判据与排错都在 `SKILL.md`（下称"手册"）**；两者说法不一致时，以手册为准。

最短路径：**跑一次初始化 → 填数据层 → 跑一次校验 → 开工**。

## 一、它为什么长这样（设计逻辑）

网申填写真正容易出错的是三件事。包里每一处设计，都是冲着其中一件去的：

| 容易出错的地方 | 包的对策 | 落点 |
|---|---|---|
| **取值会漂**：同一条信息在记忆、上一轮读数、页面现状里都有，随手取一个就可能填错 | **取值唯一真源**——一律只看数据层；快照、记忆、上一轮读数、页面现状都不算数 | 数据层（初始化时生成骨架，内容由使用者填） |
| **手法会忘**：某个系统的表单用什么方式才写得进去，不记下来下次要从头试错 | **配方**——按招聘系统／前端框架把手法记成文件，下次直接读 | 环境侧配方目录；包内 `recipes/` 只是分发副本 |
| **收工没底**：填完不知道有没有漏填、有没有被页面静默还原 | **写入必回读**（读框架状态，而不是输入框显示值）＋ **收尾逐条清点** ＋ **机械校验** | 手册 §4.4／§4.5；`scripts/verify-package.py` |

在此之上有**两条贯穿的原则**，理解了它们，包里其余的规矩基本都能推出来：

1. **单一出处**——一个口径只写一处，别处只引它的节号或路径。两处各写一份迟早会分叉，而**分叉的时候两边都不会报错**——这是手册 §5.4 记过的真实事故。
2. **能交给机器查证的，就不靠人记**——所以包里带校验器（包自洽九段 ＋ 台账运行态第十段）。改完跑一次，**退出码 0 才算完**。

**边界**也值得先说清：机器只管"怎么做"。**取值、提交、范围这三件事只能使用者定**——填数据层、点投递按钮、定禁止触碰清单。包不代填、不编造、不擅自提交。

## 二、包里有什么

| 路径 | 在设计里管什么 |
|---|---|
| `SKILL.md` | 手册：硬性要求、浏览器通道规范、流程与分层、经验闭环、自检与排错 |
| `recipes/` | 12 份配方：按招聘系统／前端框架分类的填报手法（页面内脚本、字段定位、已知的坑） |
| `scripts/init-workspace.py` | 初始化：生成项目级要求文件、台账与变更档案、数据层骨架 |
| `scripts/verify-package.py` | 机械校验：包自洽九段 ＋ 台账运行态第十段 |
| `scripts/launch-browser.bat` | 浏览器启动器模板，按配置表第 8 项替换占位符即可用 |
| `templates/CODEBUDDY.md` | 项目级要求文件的模板，由初始化脚本填充后生成 |

四类各管一件事、互不重复：**手册**管通用规矩，**配方**管某个系统怎么填，**脚本**管把环境建起来和查起来，**模板**管把规矩带进使用者的项目。

包里**不含任何个人数据**：只写"怎么做"，不写"填什么"。一切取值都来自使用者自己的数据层。

## 三、拿到之后做什么（一次性）

**第一步 · 生成骨架。** 环境里有四样东西不在包内、本机也没有：项目级要求文件、数据层、证据台账、变更档案。跑一次脚本补齐。

```bash
python scripts/init-workspace.py --plan --project "<项目根目录>"   # 先看：缺什么、将生成什么
python scripts/init-workspace.py --yes  --project "<项目根目录>"   # 生成
```

产出 5 件：项目级要求文件、台账、变更档案、数据层两份骨架。脚本**不覆盖已存在的非空文件**（要重建才加 `--force`），**不编造任何个人事实**——只搭结构。

**第二步 · 填三处只有使用者知道的东西。** 脚本只能填占位，真值填不了也不会代填。

1. **配置表 8 项**（手册 §1.1）。其中两项必填：**数据层路径**、**浏览器启动方式**——后者缺了扩展不加载，命令会 60 秒超时。
2. **数据层里的简历事实与字段取值**——这是取数的唯一真源。不填，一切填写任务都无从开始。
3. **生成的项目级要求文件里的「禁止触碰」清单**——本任务范围外的目录与共用资产，没有就留空。

**第三步 · 体检。**

```bash
python scripts/verify-package.py                                  # 包是否自洽
python scripts/verify-package.py --ledger "<本环境台账路径>"       # 再加查一轮运行态
```

期望通过、退出码 0。第二步没做之前，最多出现一条"轮次基准为空"的提示，那是初态正常现象，不是出错。

## 四、日常一轮任务

| 阶段 | 要点 |
|---|---|
| 开工 | 确认浏览器在运行、扩展已连上（**不自行拉起浏览器，请使用者启动**）；取会话，一段对话一个、整段复用 |
| 认数据 | 取值一律看数据层；快照、记忆、上一轮读数、页面现状都不算数 |
| 侦察 | **不侦察不动手**：判框架 → 对照判据表认系统 → 扫字段清单 |
| 取配方 | 三层依次取：手册 → 环境侧配方 → 数据层。配方按**文件**读，别指望技能注册表 |
| 写入 | 一个区块一次脚本、批量设值；**写完立刻回读，且读框架状态而不是 `input.value`** |
| 收尾 | 逐条清点数据层每条都有落点 → 全局回读（必填零空缺）→ 追加投递台账 → 走经验闭环 |

**三条红线**（完整版见手册 §2.1，违反即事故）：

- 绝不编造经历、时间、成绩等任何事实；
- **不擅自点击投递／提交按钮**；
- 不换浏览器通道顶替，不自行导航到别的页面。

## 五、改了东西之后

手册或配方一改，就做两件事：

1. **同步配方**：配方改在**环境侧**那一份，改完同步进包内 `recipes/`（单向：环境侧 → 包）。
2. **跑校验**：`python scripts/verify-package.py`，退出码 0 才算完。收尾那次带上 `--ledger`，会多查运行态——轮次、待验、到期、池量、登记簿对账。

## 六、出问题先看哪里

| 现象 | 去处 |
|---|---|
| 填了不生效／页面看着有值、保存后空了 | 手册 §6.2 实测失败模式表 |
| 命令返回错误、无响应、60 秒超时 | **先回读页面状态，不要盲目重跑**（重复提交会弄掉会话）；再查 §6.2 |
| 命令不报错，却落到别的页面 | 会话游标被切走：动作前先只读读一次 `location.href` 核对落点 |
| 刷新／求值报 `a dialog is currently open` | 先处理掉对话框，其后命令才恢复 |
| 上传控件赋值不了 | 手册 §3.4「上传处置」；试探不过就请使用者手动上传 |
| 要新增一个招聘系统的配方 | 手册 §4.3（怎么取配方）＋ §5.2（怎么定层落位） |
| 不确定该改哪一层 | 手册 §4.6　分层与归属 |
