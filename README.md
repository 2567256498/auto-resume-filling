# 简历网申填写 · 使用说明

这份包用于**网申／招聘表单填写**：把使用者资料库里的简历事实，填到招聘网站的表单上，填全、填对、可追溯。

本文件是上手用的简版。**完整要求、判据与排错都在 `SKILL.md`（下称"手册"）**；两者说法不一致时，以手册为准。

最短路径：**单开一个专用目录 → 跑一次初始化 → 填数据层 → 跑一次校验 → 开工**。

> **安装之后第一件事：给网申任务单开一个目录。** 手册里叫它「项目根」，本文件里叫「工作区」——初始化、数据层与附件、投递台账、开工体检、收尾清理**全都围着它转**。**不要跑在已有项目的目录、桌面或共用／同步目录里**：生成的 `CODEBUDDY.md` 是**项目级要求文件，对该目录下发起的所有会话都生效**，跑错地方等于给无关项目套上网申要求。做法见第三小节的第零步。

## 一、它为什么长这样（设计逻辑）

网申填写真正容易出错的是三件事。包里每一处设计，都是冲着其中一件去的：

| 容易出错的地方 | 包的对策 | 落点 |
|---|---|---|
| **取值会漂**：同一条信息在记忆、上一轮读数、页面现状里都有，随手取一个就可能填错 | **取值唯一真源**——一律只看数据层；快照、记忆、上一轮读数、页面现状都不算数 | 数据层（初始化时生成骨架，内容由使用者填） |
| **手法会忘**：某个系统的表单用什么方式才写得进去，不记下来下次要从头试错 | **配方**——按招聘系统／前端框架把手法记成文件，下次直接读 | 环境侧配方目录；包内 `recipes/` 只是分发副本 |
| **收工没底**：填完不知道有没有漏填、有没有被页面静默还原 | **写入必回读**（读框架状态，而不是输入框显示值）＋ **收尾逐条清点** ＋ **机械校验** | 手册 §4.4／§4.5；`scripts/verify-package.py` |

在此之上有**两条贯穿的原则**，理解了它们，包里其余的规矩基本都能推出来：

1. **单一出处**——一个口径只写一处，别处只引它的节号或路径。两处各写一份迟早会分叉，而**分叉的时候两边都不会报错**——这是手册 §5.4 记过的真实事故。
2. **能交给机器查证的，就不靠人记**——所以包里带校验器（包自洽九段 ＋ 台账运行态第十段）。改完跑一次，**退出码 0 才算完**。

**边界**也值得先说清：机器只管"怎么做"。**取值、提交、范围这三件事只能使用者定**——填数据层、点投递按钮、定禁止触碰清单。包不代填、不编造、不擅自提交。

## 二、包里有什么

| 路径 | 在设计里管什么 |
|---|---|
| `SKILL.md` | 手册：硬性要求、浏览器通道规范、流程与分层、经验闭环、自检与排错 |
| `recipes/` | 12 份配方：按招聘系统／前端框架分类的填报手法（页面内脚本、字段定位、已知的坑） |
| `scripts/init-workspace.py` | 初始化：建**信息目录**与三类运行目录，生成项目级要求文件、台账、变更档案、**投递台账**（xlsx）与数据层骨架；`--check` 当开工体检，`--clean-tmp` 清临时产物（每轮收尾跑） |
| `scripts/verify-package.py` | 机械校验，两档：**每轮档（默认）**＝运行态 ＋ 模板自证；`--package`＝包自洽九段全跑（改过封装体才需要） |
| `scripts/launch-browser.bat` | 浏览器启动器模板，按配置表第 8 项替换占位符即可用 |
| `templates/CODEBUDDY.md` | 项目级要求文件的模板，由初始化脚本填充后生成 |

四类各管一件事、互不重复：**手册**管通用规矩，**配方**管某个系统怎么填，**脚本**管把环境建起来和查起来，**模板**管把规矩带进使用者的项目。

包里**不含任何个人数据**：只写"怎么做"，不写"填什么"。一切取值都来自使用者自己的数据层。

## 三、拿到之后做什么（一次性）

**第零步 · 先给网申任务单开一个目录。** 初始化脚本要一个「项目根」，此后一切都围着它转。**新开一个专用于网申任务的目录**（空目录即可，位置随你），把简历 PDF、证件照、成绩单之类也都放进去——就地生成的信息目录 `info/` 就是它们的家。**别跑在已有项目的目录、桌面或共用／同步目录里。**

为什么非要单开：

- **要求文件对整个工作区生效**：生成的 `CODEBUDDY.md` 是项目级要求文件，对它所在目录下**发起的所有会话**都生效。跑错地方＝给无关项目套上网申要求。
- **个人数据都落在这里**：数据层、投递台账、简历 PDF、证件照都在 `info/` 下。位置固定，技能每次按绝对路径问你要附件，不用来回找；也便于你自己掌握这个目录的可见范围。
- **账才不串**：开工体检（`--check`）与收尾清理（`--clean-tmp`）都只认「项目根」；一个任务一个根，投递台账的序号才是干净的轮次锚点。

目录定下来就不要再搬——生成物里的路径已经写进了要求文件与台账。

**第一步 · 生成骨架。** 环境里有五样东西不在包内、本机也没有：项目级要求文件、数据层、**投递台账**、证据台账、变更档案。跑一次脚本补齐。

```bash
python scripts/init-workspace.py --plan --project "<项目根目录>"   # 先看：缺什么、将生成什么
python scripts/init-workspace.py --yes  --project "<项目根目录>"   # 生成
```

产出 5 件：项目级要求文件、台账、变更档案、**投递台账**（xlsx）、数据层**一份**骨架（数据层是单文件真源，不拆两份——拆开即双真源）。脚本**不覆盖已存在的非空文件**（要重建才加 `--force`），**不编造任何个人事实**——只搭结构。落点上，**信息文件统一进信息目录**（＝数据层所在目录，默认 `<项目根>/info/`）——数据层、投递台账、附件原件与其余信息文件都在里面，**项目根只留要求文件与启动器**；另建三个运行目录：`.workbuddy/tmp/`（临时，收尾清）、`.workbuddy/evidence/`（证据，留）、`.workbuddy/backup/`（改前留档，留）。

**第二步 · 填三处只有使用者知道的东西。** 脚本只能填占位，真值填不了也不会代填。

1. **配置表 8 项**（手册 §1.1）。其中两项必填：**数据层单文件路径**（写文件、不写目录——写目录会变成两份、构成双真源）、**浏览器启动方式**——后者缺了扩展不加载，命令会 60 秒超时。
2. **数据层里的简历事实与字段取值**——这是取数的唯一真源。不填，一切填写任务都无从开始。
3. **生成的项目级要求文件里的「禁止触碰」清单**——本任务范围外的目录与共用资产，没有就留空。

**第三步 · 体检。**

```bash
python scripts/verify-package.py --package                        # 封装体档：包自洽九段（改过封装体才需要）
python scripts/verify-package.py --ledger "<本环境台账路径>"       # 每轮档：运行态 ＋ 模板自证（日常收尾用这个）
```

期望通过、退出码 0。第二步没做之前，最多出现一条"轮次基准为空"的提示，那是初态正常现象，不是出错。

## 四、日常一轮任务

| 阶段 | 要点 |
|---|---|
| 开工 | **先跑部署体检**（`init-workspace.py --check`，五项必检产物缺任一项先按手册 §1.5 补齐，见手册 §4.1）；再确认浏览器在运行、扩展已连上（**不自行拉起浏览器，请使用者启动**）；取会话，一段对话一个、整段复用 |
| 认数据 | 取值一律看数据层；快照、记忆、上一轮读数、页面现状都不算数 |
| 侦察 | **不侦察不动手**：判框架 → 对照判据表认系统 → 扫字段清单 |
| 取配方 | 三层依次取：手册 → 环境侧配方 → 数据层。配方按**文件**读，别指望技能注册表 |
| 写入 | 一个区块一次脚本、批量设值；**写完立刻回读，且读框架状态而不是 `input.value`** |
| 收尾 | 逐条清点数据层每条都有落点 → 全局回读（必填零空缺） → 追加投递台账 → 走经验闭环 → **清空 `.workbuddy/tmp/`**（`--clean-tmp`） |

**三条红线**（完整版见手册 §2.1，违反即事故）：

- 绝不编造经历、时间、成绩等任何事实；
- **不擅自点击投递／提交按钮**；
- 不换浏览器通道顶替，不自行导航到别的页面。

## 五、改了东西之后

手册或配方一改，就做两件事：

1. **同步配方**：先看 `CODEBUDDY.md` 里「封装体」那一条定的是哪条路——**就地引用**时改的直接就是包内那一份，无需同步；**复制**时改在复制出来的那一份，改完单向同步进包内 `recipes/`。**同一环境同名配方只能存在一份。**
2. **跑校验**：`python scripts/verify-package.py --ledger "<本环境台账路径>"`（**每轮档**：运行态＋模板自证），退出码 0 才算完；**改过手册／配方／脚本／模板**再补一次 `--package`（**封装体档**：九段全跑）。

## 六、出问题先看哪里

| 现象 | 去处 |
|---|---|
| 填了不生效／页面看着有值、保存后空了 | 手册 §6.2 实测失败模式表 |
| 命令返回错误、无响应、60 秒超时 | **先回读页面状态，不要盲目重跑**（重复提交会弄掉会话）；再查 §6.2 |
| 命令不报错，却落到别的页面 | 会话游标被切走：动作前先只读读一次 `location.href` 核对落点 |
| 刷新／求值报 `a dialog is currently open` | 先处理掉对话框，其后命令才恢复 |
| 上传控件赋值不了 | 手册 §3.4「上传处置」；试探不过就请使用者手动上传 |
| 要新增一个招聘系统的配方 | 手册 §4.3（怎么取配方）＋ §5.2（怎么定层落位） |
| 不确定该改哪一层 | 手册 §4.6　分层与归属 |
| 台账／投递台账／要求文件不见了 | 多半是本项目没跑过初始化——跑 `init-workspace.py --check` 看缺哪几项，再按手册 §1.5 补 |
| 根目录越用越乱、堆了一堆临时文件 | 落点没按三目录归位：临时产物进 `.workbuddy/tmp/`（收尾跑 `--clean-tmp` 清）、截图证据进 `evidence/`、改前留档进 `backup/`；信息文件一律进信息目录（手册 §3.7.11） |

| 初始化跑错了目录（无关项目被套上网申要求） | 把该目录下生成的 `CODEBUDDY.md`、`info/`、`.workbuddy/` 移走或删除（先确认 `info/` 里没有你要的资料），再到正确的专用目录重新初始化；单开目录的理由见第三小节第零步 |

## 七、章节地图

`§一` 部署配置与移交 ｜ `§二` 任务定义与硬性要求 ｜ `§三` 浏览器通道规范 ｜ `§四` 流程与分层 ｜ `§五` 持续优化闭环 ｜ `§六` 自检与排错 ｜ `附录` 台账／变更档案／投递台账模板块（脚本就地抽取，别单独改）

版本以 `SKILL.md` 的 frontmatter 为准；**封装体自身的发布历史见 `CHANGELOG.md`**，使用者在自己的项目里发生的事件见初始化时生成的变更档案。
